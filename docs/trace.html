Tester vos applications Mac
dans un faux Mac, avant de les télécharger

Un site hébergé sur GitHub Pages où l'internaute arrive devant un Mac 16:9 dans son navigateur, y lance vos applications comme chez lui et ne télécharge qu'ensuite. Ce document garde les trois propositions de maquette, les commentaires de chaque approche et les décisions prises avec Stéphan.

Cahier des charges de départ

  • Finder personnalisé au format 16:9, applications rangées dans le Dock et sur le Bureau, prêtes à être lancées.
  • Test en direct de chaque application avant téléchargement.
  • Réalisation professionnelle, fluide, performante, style épuré Apple.
  • Maquettes à choisir avant d'écrire le code.

Matière utilisée

  • Vos vraies icônes, 32 applications au total.
  • Les captures déjà réalisées pour skyrimtools.com.
  • Les dépôts GitHub starbudweiser/* pour les téléchargements.

Proposition A

Vitrine et écran

Retenue pour l'entrée

L'idée

Une page produit à la Apple : titre, un seul bouton, puis le Mac dans un cadre fin. Un clic sur « Allumer le Mac » l'agrandit en plein écran, sur le bureau Skyrim.

Pour

  • Raconte l'histoire avant de montrer les 32 applis
  • Le plus proche d'une page Apple
  • Un seul chemin clair : lire, allumer, essayer

Contre

  • Dock et bureau n'affichent qu'une dizaine d'applis par bureau
  • Deux écrans à concevoir : la page et le Mac

Commentaire de l'approche

Fond blanc, titre à dégradé bleu-violet sur la seule seconde ligne, un bouton plein bleu : tout le poids visuel va à l'écran du Mac, qui est le produit. Le cadre noir fin évoque un écran Apple sans imiter un modèle précis. C'est la meilleure porte d'entrée, mais elle ne suffit pas à explorer 32 applis : d'où l'association avec C.

Proposition B

Launchpad et Mission Control

Non retenue seule

L'idée

Le site est le Mac dès la première seconde. Mission Control montre les deux bureaux, le Launchpad toutes les applis du bureau actif.

Pour

  • Effet « waouh » immédiat, aucun texte avant la démo
  • Toutes les applis d'un bureau visibles sans défiler
  • Les deux bureaux se comprennent d'un coup d'œil

Contre

  • Peu de place pour expliquer, rassurer et référencer le site
  • Le Finder reste à créer pour les fiches détaillées

Commentaire de l'approche

Thème sombre, verre givré et icônes agrandies : c'est la version la plus spectaculaire. Elle sert de modèle pour deux éléments conservés dans le site final : la bascule entre bureaux et la recherche rapide (Spotlight) pour retrouver une application parmi 32.

Proposition C

Finder en vue Galerie

Retenue pour le Mac allumé

L'idée

Un Finder en vue Galerie : l'application choisie s'affiche en grand, la bande d'icônes permet de feuilleter, le panneau d'informations porte les boutons « Ouvrir la démo » et « Télécharger ». Chaque bureau est une collection de la barre latérale.

Pour

  • Le plus fidèle au geste d'un Mac
  • Une fiche par application sans quitter l'écran
  • Prévu pour 32 applis et plus

Contre

  • Moins spectaculaire au premier regard
  • Demande une zone d'aperçu soignée pour chaque appli

Commentaire de l'approche

C'est l'écran où le visiteur passe le plus de temps. L'aperçu central affiche l'application en action, la bande du bas sert de navigation, et le panneau de droite concentre les deux actions qui comptent. Les captures réelles des applis et les démos interactives viendront remplir la zone d'aperçu.

Décisions et suite

Ce qui a été choisi le 9 novembre 2026

Réponses de Stéphan

QuestionRéponse
DirectionA pour l'entrée, C pour le Mac allumé
DémosRépliques interactives pour les applis phares (dont mTRANSLATOR), parcours guidé pour les autres
AdresseGitHub Pages, adresse github.io

Exigences ajoutées

  • Thèmes clair et sombre.
  • Choix du fond d'écran, une dizaine à créer.
  • Sons d'interface.
  • Ajouter ou retirer une application côté auteur, pas côté internaute.
  • « À propos » dans le menu pomme.
  • Effet « waouh » entretenu à chaque étape.
  • À l'entrée, simulation d'un démarrage de Mac avec le son de démarrage.

Choix techniques arrêtés

  • Site statique (HTML, CSS, JavaScript natifs) servi par GitHub Pages, sans étape de compilation.
  • Liste des applis dans un fichier de données unique, avec un outil en ligne de commande pour ajouter ou retirer une appli.
  • Bureau 16:9 mis à l'échelle de la fenêtre, quatre langues (français, anglais, espagnol, italien).
  • Fonds d'écran générés en local avec FLUX 3 Klein (10 images).
  • Sons de l'interface et son de démarrage synthétisés dans le navigateur (aucun fichier audio tiers, aucune copie du son Apple).
  • Version des applis lue en direct sur GitHub Releases ; « Bientôt disponible » quand l'appli n'a pas de version publique.

Prochaines étapes

  • Noyau : démarrage, Dock, fenêtres, deux bureaux.
  • Finder galerie, Spotlight, menus, « À propos ».
  • Démos phares : sKYCRASH, mTRANSLATOR, mCLEAN, mSTICK ; parcours guidé pour les autres.
  • Essais dans le navigateur, puis publication sur GitHub Pages après validation de Stéphan.
